Pixels2Physiology · an automation case study

Heart records trapped on paper, turned back into data.

Hospitals hold decades of ECGs only as printouts, scans and phone photos. A computer can't analyse a photo of a heartbeat. This pipeline takes the picture, however battered, and gives back the original electrical signal, automatically, on an ordinary laptop.

The problem

A photo is not a measurement

An ECG printout is a drawing of a signal on a grid. To use it for research, AI diagnosis or a patient's electronic record, someone has to read every wiggle back off the paper. By hand, that takes far too long to do at scale.

And real records are messy: scanned in colour or black and white, photographed on a desk or off a screen, stained, creased, sideways, upside down, mouldy.

📄 photo / scan→ ⚙️ automated pipeline→ 📈 12 signals in millivolts (CSV)

From a model to an automation

Built to be run, not just demoed

A model in a notebook helps nobody. The same steps are packaged as a small tool: point it at a folder of scans and it produces one data file per record, plus a one-page check sheet that a person can glance at.

1 · Drop in

A folder of scans or phone photos. Any size, any orientation.

2 · Process

scripts/digitise.py folder/ runs all six steps on each page, about 4 seconds a page on a laptop.

3 · Output

A CSV per record with 12 leads in millivolts, ready for a database or an analysis tool.

4 · Human check

Pages where a strip comes back empty are flagged. A one-page visual check sheet makes review take seconds.

5 · Measure

scripts/evaluate.py re-scores the system against known answers whenever it changes.

Modular

Each step is its own file with one job. Any step can be swapped, for example a different page layout, without touching the rest.

Runs locally

No cloud and no API calls. Medical images never leave the machine, which keeps data protection simple.

Measured, not assumed

Success is defined as a number before the work starts, re-checked on records the system has never seen, and reported per damage type so a weak spot can't hide in an average.

Under the hood

For the technical reader

Architecture

UNet-1 (5-level U-Net, 1-channel 512×656 input) segments the document. Its training masks were generated automatically: ORB keypoints and a RANSAC homography between each damaged image and its clean original, with no manual labelling. Trained with BCE + Dice, AdamW 1e-3, 10 epochs.

Crop: morphological close (15×15), largest contour, minimum-area rectangle, perspective warp to 2200×1700.

UNet-2 (residual U-Net with CBAM attention on every skip) segments the trace on each 384×2192 strip. It takes 2 channels: grayscale plus log FFT magnitude, because the printed grid is periodic and shows up as sharp peaks in frequency space. Targets are rendered from the true signal. Trained with Dice + BCE, Adam 1e-4, 40 epochs.

Orientation: if any strip has no ink more than 50 px from its busiest row, the page is rotated 180° and re-run.

Digitise: 2×2 opening, a median baseline, the furthest-from-baseline pixel per column, (baseline − y) × 0.5/39 mV, and a cubic resample to the record length.

How the error is measured

RMSE in millivolts, per lead, after the metric aligns the recovered trace to the original. It allows up to ±0.2 s of time shift and one constant vertical offset, so a correct trace that starts a few pixels late or sits on a different baseline is not punished for that alone. Leads are averaged with equal weight.

Two bugs I found while re-running it for this page

Rebuilding the notebook as a package, with tests, turned up two problems. Both are fixed here, and the original behaviour is kept behind a flag so the paper's number can still be reproduced.

1 · The evaluation shifted traces the wrong way. It found the right time lag between the recovered and true signal, then applied it in the opposite direction, doubling the misalignment instead of removing it. This only ever made the scores worse.

2 · The upside-down check fired too often. A quiet lead such as aVR can look flat on an upright page, which triggered a 180° flip. The pipeline now compares both orientations and keeps the better one.
